# 参数化调用与 Provider 自建操作面板方案

状态：设计提案，尚未实施。本文中的接口、版本与模块名是拟议合同，不代表当前 SDK 已提供。当前运行协议仍为 SDK / Provider API 1.0.0。

本方案依据用户确认及只读架构审查。现行约束见 [PERFORMANCE.md](../../PERFORMANCE.md)、[DESIGN.md](../../DESIGN.md)、[i18n.md](../../i18n.md)、[SDK 协议](../../lychee-sdk/docs/PROTOCOLS.md)和[存储归属](../../lychee-sdk/docs/STORAGE.md)。实施时将正式公共合同迁入 SDK 文档，本文保留决策与实施依赖，不成为第二份现行协议。

## 1. 用户结果与范围

用户可以搜索“主音量 30%”，确认执行后将主音量设为 30%；再次使用最近记录会重放这个具体调用。搜索“音量”后右键，由音量 Provider 构建操作面板，列出当前支持的音量通道并直接调整。搜索、面板和历史使用同一动作定义与规范化调用。

已确认的产品决策：

- 最近使用保存具体动作、目标和参数；收藏同时支持对象/命令入口与具体调用，显示名称明确区分。
- 参数缺失进入补参；非法参数保留原输入并给简短说明，不偷偷修改值。
- 支持关键词、别名、明确常见句式及本地化；不依赖复杂自然语言理解。音量第一版省略通道时明确指主音量，只做绝对设置。
- 右键是 Provider 提供的操作面板，可以有状态、动作、参数、预览与进一步导航。
- **Provider 自行构建面板与控件。** 滑块、颜色选择器、组合操作等不由 Host 按 schema 自动生成。公共组件是可选工具，不是扩展能力上限。
- SDK 统一数据校验、调用、完成、恢复和资源管理；视觉遵守公共规范。
- 不增加使用次数或时间戳，不加入倒计时，不将参数塞入 payload 作为替代正式协议的方案。

本轮只制定方案；不新增音量运行代码，不改现行注册协议、存档或游戏副本。

## 2. 职责与复用

| 所有者 | 负责 | 不负责 |
| --- | --- | --- |
| Host | 搜索路由、候选合并排序、面板容器/定位/焦点、调用入口、最近和收藏、错误呈现 | Provider 业务 DB、控件业务含义、全量设置目录 |
| SDK 公共模块 | 参数词法和 schema 校验、引用/调用规范化、执行与编辑会话、取消及完成、恢复工具、主题与托管资源 | 根据 schema 生成任意面板、猜测上游函数的含义 |
| Provider | 动作/目标语义、业务读写、动态能力、状态观察、面板与控件构建、补参界面、目标恢复与迁移 | 私自写入 Host 历史，绕过统一入口提交需要记录的业务操作 |
| 第三方 Adapter | 将已核实的目标标识、读取/执行/结果证据映射到同一公共合同 | 从 label 或 setter 名称推断可写能力，为恢复预建全部页面 |

Provider 可调用公共组件，也可使用自建 Frame 或已有受管理视图。草稿变化、预览布局、焦点与滚动是局部 UI 行为，不必生成 Invocation；实际业务写入才走调用入口。Provider 提供执行函数，SDK 调用它，不是 SDK 直接写业务设置。

继续复用 Provider 注册隔离与实例身份、InteractionBinding、安全点击 Broker、Resources、ViewHost、公共主题/菜单/Tooltip、CharacterStore 和截断前排名。新增执行管理不得复制现有定时器/事件管理器；新增面板容器不得重做一套 UI Runtime。

## 3. 公开数据模型

所有公开记录保持具名字段、隔离复制和严格白名单。持久记录不得含回调、Frame、当前值快照、准备凭据或运行时序号。

| 模型 | 含义与必要内容 |
| --- | --- |
| Entry | 搜索和列表展示记录，仍可仅代表可浏览对象；不等于一次执行 |
| TargetRef | `version` 与 Provider 自有的有界 `key`；表达稳定业务目标，例如音量通道 ID |
| Action | 稳定 actionID、显示说明、参数合同、执行类型、恢复能力和可选交互方式 |
| Invocation | providerID、actionID、动作数据版本、TargetRef、完整规范化 args；描述一次具体操作 |
| PreparedInvocation | 仅会话可用的 SDK 私有句柄；绑定当前 Provider 实例、目标身份和能力版本，不可持久化或伪造 |
| StoredRef | 带 kind 的旧 Entry、Target、Command 或 Invocation 引用，包含产品身份与必要显示回退 |

示例是拟议数据格式：

```lua
{
    kind = "invocation",
    product = "retail",
    providerID = "lychee.audio",
    actionID = "set-volume",
    actionVersion = 1,
    target = { version = 1, key = { channel = "master" } },
    args = { percent = 30 },
}
```

入口引用和具体调用的区别：Target 收藏浏览某对象；Command 收藏某个动作及可选稳定目标，缺参数时补参；Invocation 收藏完整调用。显示例如“主音量”“设置主音量…”“主音量设为 30%”。用户看到哪一种就恢复哪一种，不静默把具体动作降为打开页面。

### 3.1 规范化与判等

- 动作 schema 定义类型、必填、明确默认值、范围、步长、单位及稳定枚举 ID。基础参数为 string / number / integer / boolean / enum / 有界列表，第一版不引入任意可执行条件表达式。
- 默认值在准备完成时展开进具体调用；省略通道按已声明规则变成 master。未完成草稿不能作为具体调用保存。
- 合法等价输入可得到相同值，例如 `30` 与 `30.0`；拒绝非有限数、超范围、不符合步长、未知字段，不做舍入或夹取。可空字段须显式声明，缺省与空值含义固定。
- 参数键顺序不影响身份；数组顺序有意义，除非 schema 显式声明集合。采用有界结构判等或确定性编码；hash 只是索引加速，必须核对原值，不能以碰撞误合并。
- 具体调用判等包含产品、Provider、动作、目标及规范化参数；迁移后按当前语义判等。动作版本与目标引用版本不是 SDK 版本，也不是当前值修订。
- 步长/精度验证使用 schema 明确的十进制精度策略，不用不稳定的浮点余数判定合法值；原始数字文字保留到校验结束。

## 4. Provider 声明与最小接入

建议在新版本中提供以下能力；名字在正式 SDK 类型阶段冻结。生命周期阶段并不等于全部必须实现的回调。

| 能力 | 最小责任 |
| --- | --- |
| `actions[actionID]` | 必填显示合同、actionVersion、执行类型、参数 schema、执行函数；简单动作可同步完成 |
| `describe(target, actionID, context, reply)` | 可选，为动态目标返回纯数据能力、参数约束和可用原因；静态动作使用注册声明 |
| `resolveTarget(ref, context, reply)` | 声明持久恢复能力时必需，允许同步回复或可取消异步回复 |
| `observe(target, context, publish)` | 可选，仅活动面板订阅状态，发布 stateRevision 及当前值；返回取消句柄 |
| `parse` 或 SDK 句式声明 | 可选，将搜索原文转换成标准解析结果；普通对象搜索保持现有 query |
| `panels[panelID] = {create,...}` | Provider 构建操作/补参面板，复用既有 Mount/Unmount/Dispose 语义 |

拟议 Host 授予的面板上下文方法：`Prepare(actionID,target,args,reply)`、`Invoke(prepared,reply)`、`BeginEdit(actionID,target,options)`。上下文限定所属 Provider 及原始目标能力，Provider 不能用公开 providerID 字符串绕过实例授权；任意新目标必须先走同一准备校验。

描述结果只能引用本 Provider 已注册的 actionID/panelID，动态数据不能携带新执行函数。动态约束可以依目标变化，必须给出能力修订；相关参数变化时重新描述和校验，保留草稿并指出失效字段，不静默清空或选择新枚举值。

准备只解析、读状态和验证，不产生业务写入。最终 Invoke 再核对 Provider 实例、目标身份、能力、权限/战斗状态。安全技能/物品仍由 Host Broker 使用合法物理点击，不能通过普通 Invoke 绕过；拖动仍保留自己的语义及成功证据。

## 5. 搜索、补参与本地化

链路：路由 → 原文参数解析 → Provider 业务目标解析 → schema 校验 → 展示候选/补参/错误 → 用户执行 → 同一调用入口。

解析结果为 `notMatched / incomplete / invalid / ambiguous / ready`。已经明确匹配命令但参数非法时，该候选显示错误并保留输入，Enter 不执行替代默认值；无关对象结果可以继续展示。搜索本身只形成候选，不能执行业务动作。

- 使用原文词法处理数字、符号、单位及字符串参数；现有 Normalizer 只用于搜索匹配。当前 routed raw 去掉了入口前缀，因此同时保留完整原文与路由偏移，字段错误能定位原输入。
- SDK 句式采用有界、锚定的字面词与参数槽，不向 Provider 暴露任意正则执行引擎。不枚举全部目标×句式×参数组合。
- 缺参优先进入该 Provider 声明的补参面板；命令若允许缺参搜索就必须有补参入口。Host 不根据 schema 自动拼表单。Provider 可用 SDK 返回的字段错误标注自己的控件。
- 多个明确匹配来源显示候选，不自动根据历史选择业务来源。显式用户前缀优先，跨来源声明冲突继续走公开校验。
- 句式、别名、单位、枚举显示、面板标签、错误和历史格式都通过 i18n。稳定 ID 不翻译；游戏目标优先使用当前客户端名称；持久显示回退不作为恢复身份。
- 输入 locale 与保存的规范化参数分开。zhCN/enUS 必测，zhTW/enGB 使用规定家族回退；不把中文逐字规则套给所有语言。
- 友好错误例如“请输入 0–100 的数值”“此设置暂不可用”；稳定错误码供诊断。解析错误不改写输入，不把 `-1%` 当成 `1%`。

## 6. 执行与完成

每次执行得到唯一的临时 operationID，不持久化，也不作为时间戳/使用次数。SDK 先建立必要的结果关联，再 dispatch，允许同步完成。

```text
prepared → dispatching → pending → succeeded / failed / cancelled / indeterminate
                   └────────────→ 同步终态
```

`accepted/pending` 不是成功。`cancelRequested` 是请求标志，只有确认业务不会再生效才进入 cancelled。`indeterminate` 表示业务可能已生效但没有足够证据，不记成功、不自动重试。终态只消费一次，重复/迟到回调不能刷新历史或重新打开页面。

| 事件 | UI 与业务规则 |
| --- | --- |
| 换搜索词、关闭参数面板 | 结束解析/准备/观察，取消未 dispatch 工作；已 dispatch 操作不冒充已取消 |
| 关闭面板，Provider 仍启用 | 已提交操作的有界 operation scope 可等待结果；与旧 UI 断开，成功可更新原角色历史，但不导航/重新开窗 |
| 禁用、注销、进入战斗、角色变化 | 停止新 dispatch，调用取消钩子并关闭旧实例资源；未确认结束的操作终结为 indeterminate，不把回调交给新实例或新角色 |
| 超时 | 只停止 SDK 等待，不保证外部操作停止；根据是否已 dispatch 产生明确失败或 indeterminate |
| 业务成功但后续页面打开失败 | 业务结果保留成功并只记一次历史，导航错误单独呈现 |

operation scope 复用 Resources 的实现，属于 Provider 启用生命周期而不是 query/view 子作用域；它只保留完成所需的有界数据，不保留 Frame/草稿/整页 context。Provider 禁用后资源仍须归零，不增加永久等待的后台任务。

Provider 负责定义“成功”证据：同步返回必须代表已完成，异步使用可关联的完成事件或回读。SDK 保证本次终态至多记一次，不能声称外部系统恰好执行一次。不能仅凭函数不抛错推断业务成功；不会自动重试非幂等操作。

## 7. 连续编辑：与控件类型无关

BeginEdit 适用于 Provider 构建的滑块、拖动颜色、旋钮、预览调整等；SDK 不识别控件种类。Provider 决定 begin/update/end/cancel 的交互时机、草稿呈现与应用模式，SDK 统一执行顺序和历史合并。

### 7.1 身份与状态

分开维护 Provider 实例身份、目标实例身份、能力/schema 修订、业务 stateRevision、手势绑定代次。目标替换/能力撤销/禁用使手势失效；当前值变化和无关 UI 更新不改变操作目标。不得取消现有普通按钮的重绑保护来迁就连续控件。

编辑会话保存 `draft / lastApplied / pending / finalRequested` 和临时序号。Provider 观察到值变化时附可用的写入关联标识，SDK 区分自身反馈与外部变更；无法可靠关联时只允许可证明正确的结束提交或显式冲突策略，不靠时间窗口猜测。

### 7.2 顺序与建议默认行为

- Provider 声明业务冲突 key，通常是目标＋设置字段；同目标从搜索、面板、历史进入都共享调度，不按控件 ID 各自排队。
- 可覆盖的绝对设置采用一个在途＋一个最新待提交值。前一次完成后再发最新值；忽略旧回调不能代替控制写入顺序。跨动作修改同一底层字段时复用同一冲突 key。
- 增量、购买或其他非幂等动作不能开启 latest 模式，采用有界顺序或明确忙碌拒绝，绝不静默吞操作。
- 一般动作完成前禁止重复提交同一请求；不同目标可以在总额度内独立执行。目标冲突时不能让两次拖动交错接管。
- 正常松手标记 finalRequested，确保最新值完成或给出失败。关闭/失效取消尚未 dispatch 的值，不隐式发送最后草稿，不把关闭当撤销。
- **建议默认**：音量实时应用；外部修改发生时停止未发值，显示实际状态并保留草稿供重新操作；不自动覆盖外部值。
- **建议默认**：一次编辑最多记一条历史，使用最后确认成功的调用。中间成功而最终失败/关闭时保留已生效值并据此记一条；从未确认成功则不记。实时界面清楚区分草稿与实际值。
- **建议默认**：未变化拖动不记历史；用户明确重放已等于当前值的绝对调用，可在验证目标后按成功刷新最近顺序，不必再次调用原生 setter。
- 如果某次已提交操作结果未知且可能继续覆盖目标，该目标进入冲突状态：清未发队列、禁止继续自动 dispatch，直到 Provider 提供可靠收尾/恢复证据。一次回读相等不足以证明未知旧请求不会再生效。

这些默认行为是本提案的建议，和第 1 节已经明确确认的产品决策区分记录；实施不需要重新询问已确认事项。

## 8. Provider 面板宿主合同

Entry 可引用已注册的操作 panelID。右键时 Host 重新验证条目，按需解析动态能力，再挂载 Provider 实例。未声明面板的旧 Provider 继续使用现有按钮菜单。

- Host 提供容器、锚点、可用宽高、主题访问、托管资源、受限动作上下文和 Resize/Close。Provider 创建内部结构并决定控件、布局、状态和事件。
- Provider 使用公共圆角表面、字体、间距、状态色与交互规范；公共组件可选。自建控件同样需要可见焦点、禁用态、合理点击区域及键盘操作。
- 同时只有一个操作浮层。外部点击关闭仅针对整个面板之外；内部拖动和输入焦点不能被当成外部关闭。失效、重绑或战斗立即阻断旧交互。
- Esc 先由明确的局部编辑语义处理，再关闭操作面板，不连带执行或确认草稿。返回搜索的导航与普通关闭继续遵循 Host 统一规则。
- Host 的“固定入口”“固定具体调用”“别名”使用标准功能区；Provider 提供当前可保存调用的有效状态，Host 不读取控件内部变量推断参数。
- 深层内容可以通过明确导航打开既有受管理页面；挂载失败保留原页面/焦点。打开新页不会再次执行已成功的业务动作。
- 面板实例和控件按有限种类复用，解绑时清空目标/观察/准备凭据；禁止按 targetID 永久缓存一棵 Frame 树。SDK 可计量宿主资源，不能声称能沙箱限制第三方私自创建 Frame。
- 不把通用 Slider/Select 节点作为本功能前置要求；音量 Provider 可使用经过版本核实的原生控件并应用主题。出现第二个实际复用需求时再抽公共 UI 组件。

## 9. 持久恢复、收藏与排序

Host 保存有界稳定引用和显示回退；业务真实设置仍归 Provider/游戏/上游插件。第一版沿用角色与产品隔离，不提升到账号共享，不保存当前业务状态副本。

- 旧 Entry 记录迁移成显式 legacy-entry 分支，保持打开对象的旧语义，不猜以前执行了哪个次要动作。
- Invocation 恢复顺序：原始存档有界校验 → 动作/目标数据迁移 → 稳定目标恢复 → 当前能力及参数校验 → 当前语言展示。恢复不执行。
- 恢复区分 ready、notReady、temporarilyUnavailable、deleted、incompatible；异步恢复可取消，按可见需要进行，不为首页加载全部设置页。
- 删除、未来版本、迁移缺失及损坏记录不自动按名称替换或清除。可显示不可用占位并允许用户定向移除；未知原始数据保留且阻止破坏性回写。
- 参数范围变小或枚举消失时提示修正，保留原值，不夹取。修改具体收藏必须显式保存，不把编辑历史候选自动写回收藏。
- 普通偏好映射到命令/目标用于截断前选择；具体调用按完整语义判等。Provider 先确认文本和显式参数兼容，再使用偏好，不让“音量 50”带出历史 30 的参数。
- 多个参数收藏投影到同一命令时收藏权重取一次，最近顺序取最高适用权重；不靠收藏更多参数无限叠分。Entry 内代表候选、Provider Top K 和 Host 合并使用同一规则。
- 保持先匹配、后加权、再截断；不会为所有历史参数组合物化候选。未提供参数时可以展示明确标注的最近调用建议，同时保留无参数入口。
- 最近使用按确认完成更新，编辑会话只收尾一次；并发不同目标按完成顺序排列，不需要持久时间戳或计数。

## 10. 版本与迁移发布

建议新合同使用 **SDK / Provider API 1.1.0**，作为显式增加能力的版本；是否维持这一版本号须在接口冻结时以兼容矩阵验证，而不是只改字符串。此文不改 tools/sdk_contract.json 或当前 Supports 行为。

| 组合 | 拟议行为 |
| --- | --- |
| 新 Host + 1.0.0 Provider | 保留单独的 1.0.0 校验与同步动作入口，继续旧 Entry 历史、菜单和恢复；不伪称支持参数调用 |
| 新 Host + 1.1.0 Provider | 使用新调用/面板合同；普通 query、安全动作及 View 基础可复用 |
| 旧 Host + 新 Provider | 在 Supports 检查时明确不支持；不偷偷降级丢参数，不执行部分注册 |
| 新 Host + 未来未知版本 | 拒绝注册并保留存档 |

Supports 从单一相等判断改为显式受支持版本集合；新旧版本分别校验字段和回调形状，汇入内部执行模型但不改变旧 run(entry,context) 的语义。保留旧版本与新增合同均需公开示例验证，不通过宽松白名单“兼容”。已退役数字 API/私有 Command 注册不恢复。

SDK 发布版本、最新公共 API、类型、帮助模块、错误码和交付清单同步升级；动作数据版本与目标引用版本按业务分别迁移。纯 Provider 自建控件不要求提升 UI Runtime 1；若公开 UI 合同确需不兼容改变，独立处理并验证。

## 11. 成本与生命周期设计

性能规则和数字唯一归 PERFORMANCE.md。本提案不在此建立另一份预算或放宽现有阈值。正式实施的第一步必须在该文件为新能力增加专项容量/测量条目，并同时保留既有硬门禁；没有落实数值的新增路径不得进入运行代码阶段。

| 路径 | 工作量与资源策略 | 必须测量 |
| --- | --- | --- |
| 首次查询 | 按已路由动作的有界句式解析；不调用业务写入，不建控件 | 首结果延迟、总 CPU、最大批次、分配 |
| 右键首次/温打开 | 描述当前目标，按需建一份可复用 Provider 面板 | Frame/Region 高水位、当前 schema/文本保留、首次和温延迟 |
| 连续输入 | 草稿局部更新；同目标在途和待发工作有界 | 原始事件数、实际 dispatch 数、峰值、最终提交延迟 |
| 查询/面板关闭 | 解析/观察/未发工作清理，已发完成最小化保留 | timer/事件/队列、旧目标/context 是否释放 |
| 历史恢复 | 只恢复必要可见引用，异步复用限额 | 冷/温恢复成本、不预建 UI、不可用分类 |
| 停用/注销 | 资源归零，旧回调不能接管新实例 | 稳定内存、零后台工作及 reentry |

新增专项容量必须覆盖：参数字段/深度/节点/逻辑字节、句式和歧义候选、动态枚举与分页、描述缓存及修订、operation 和编辑会话数、排队动作与结果缓冲、引用总量与单条字节、面板实例和控件池。每项明确超限错误、淘汰及清理，不只限制条数。

复用当前 Provider 总资源、固定/最近引用、候选回复和 Top K 的额度；需要增加任何额度时先记录产品理由和独立测量，不靠默认关闭来源、减少结果、频繁 GC 或拆统计口径通过。持续状态观察优先事件驱动，活动拖动可以使用唯一有界驱动，空闲不新增轮询。SDK 不能抢占第三方同步回调，首次业务调用和引擎成本必须独立实测。

下列文件分工是拟议范围；新模块应先确认加载预算、实际复用与 SDK 发布清单。共享文件按依赖顺序集成，不同时混改。

## 13. 最小完整验收矩阵

1. 搜索、Provider 自建控件、最近重放得到同一规范化 Invocation；目标入口、命令入口和 30%/50% 收藏互不合并。
2. `-1%`、小数、步长不符、超范围、空值、缺参、未知枚举、歧义与超长输入：保留原文，未 ready 不执行。
3. 参数含点号、负号和单位时不经过有损搜索规范化；前缀路由后的错误仍定位完整输入；zhCN/enUS 及 zhTW/enGB 回退覆盖。
4. describe/resolve/prepare 均无写入；同时验证同步回复、异步、失败、重复回复、注销重注册、回调内重入。
5. 自身 state 更新和无关 UI 更新不打断手势；目标重绑、能力移除、旧按下、隐藏重开必须拒绝旧操作。
6. 故意让 Adapter 乱序完成：实际最终值仍正确；同目标搜索与面板并发有序；非幂等动作不丢弃、不自动重试。
7. 松手最后值完成、关闭丢未发值、中途成功最终失败、结果未知、外部修改冲突、无变化拖动；每会话历史最多一条。
8. 业务已提交后换词/关闭/战斗/禁用/注销/角色切换：不把失去观察误报取消，不向新 UI/角色回流；业务成功与导航失败分开。
9. 旧 Entry 存档、损坏/未来版本、目标删除、暂未就绪、迁移失败及范围变小：原始数据保留，不按相似名称替换。
10. 满容量收藏/最近中偏好目标位于 Provider 前 20 之外仍可进入候选；历史 30 不覆盖显式 50；多个参数收藏不能无限加权。
11. 反复打开不同目标/schema、滚动、自建控件与焦点切换：控件池高水位稳定，卸载清引用，禁用资源零活动；不为恢复预建上游页面。
12. 新 Host 配旧/新 Provider、旧 Host 配新 Provider，以及安全技能/物品/拖动的既有真实入口完整回归。

相关现有测试可复用 providers、sdk、search、ui 和 integration 目录的边界与原生替身；新行为从公开入口验证，并有独立业务参照，不只比较两个同源实现。实施后的完整入口为 `python tests/run.py`，运行时变更另做 wowdoc validate、git diff --check 及客户端检查；不得把离线替身等同实机验证。
