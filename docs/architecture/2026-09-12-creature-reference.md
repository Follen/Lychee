# LDT 内置怪物资料 Provider（仅正式服）

用户确认：全局搜索小怪、Boss、技能名及“毒牙老二”式简称，点击在荔枝内展示原生游戏模型与怪物资料。保留现有许可证；重新编写实现，资料仅整理事实字段。无需安装、加载或修改其他插件。

## 边界与成本计划

- `Data.lua` 由具名 JSON 事实记录生成；构建时校验容量和关系。模型文件与技能正文不打包。
- `Catalog.lua` 管理本次查询的数据、匹配与稳定身份；Provider 通过公开 SDK query/resolve/view 接入，详情页独立消费记录。通用搜索引擎不加入怪物领域分支，公开记录保持具名字段；规范化仅增加可选的跳过缓存参数，默认行为不变。
- 全局默认开启，保留 `ldt:` 可选前缀。技能返回所属怪物，传递明确的 spellID 定位技能；同名、不同副本的记录不能合并。Boss 序号按地下城手册核验，无可信映射则不生成序号别名。
- 未查询不物化目录、不创建界面、事件和定时器。每查询最多 4096 怪物、每怪最多64技能，每128项或1ms通过 SDK resources 让出。候选最多20条，逐副本展开，取消释放临时目录。
- 技能仅保存ID和事实标记；`C_Spell.GetSpellName` 按当前客户端语言动态读取，不建全量名称缓存或第二份索引。通用规范化允许显式 `cache=false`，仅保留当前少量结果。精确怪物名、NPC ID、Boss序号及空前缀查询优先完成，不扫描无关技能；其他词查询需逐条读取技能名称，缺失时分批请求游戏数据并通过事件恢复。最多等待2秒后对可用数据重扫；SDK整体超时仍有效。
- 缺失技能请求可能使游戏自身加载缓存，不能据此宣称整个客户端内存零增长。事件先订阅再请求，覆盖同步完成、失败、超时、取消；不在等待期间轮询。连续查询不保留跨查询待办或名称，可能重新请求尚未完成的数据。
- 原始事实仅作为生成器常量保留；模型和详情行首次访问创建后复用。详情页只创建一个模型和6个技能行；翻页重新绑定，卸载清除模型、数据、状态与事件。
- 旧 TOC 离线基线：83文件，1340.3 KiB回收后保留，41ms；已有1346 KiB/46ms门禁保持用于原有模块。新增功能单独预算加载保留512 KiB、CPU15ms；完整加载总预算1858 KiB/61ms。新增功能预算在实施前独立制定，不以减少旧目录或数据量达到指标。
- 新功能首次查询保留<2048 KiB；20次查询累计分配<32768 KiB，关闭回收后增长<128 KiB；无空闲任务。查询延迟与单批CPU另外记录，不把让出视为抢占。
- 游戏模型显存/引擎资源不计入Lua堆；实机冷查询、模型取景、拖动、长技能名、返回、战斗关闭须另行验证。

## 验收重点

全局/前缀、中文英文、NPC/技能ID、简称序号、多怪共用技能、无结果、取消、角色禁用恢复、固定恢复稳定身份、禁用关闭、模型失败与重开、技能行复用与无空闲驱动。数据版本与生成器漂移纳入构建门禁。

当前数据规模16副本/462怪物/1539不同技能。怪物名称属于生成快照中的具名事实；技能名称不打包、不写SV。中文客户端按中文技能名搜索，英文客户端按英文名搜索；未承诺跨客户端语言的技能名称搜索。
