# 紧凑搜索存储

基线：28f97751306c1cd5460645bc18fbfaa5eabb8b37。用户要求可扩展、SDK/文档同步、简单高效。本轮只重构内部存储，不改变角色设置、默认来源、加载和动画生命周期。

## 设计与实施前预算

Search Storage 集中管理内部记录和索引行的紧凑布局；共享元表仅用于 Host 具名字段访问，固定常用字段连续存储，其他字符串字段按需保存，未来扩展不要求 Provider 了解下标。非字符串扩展键回退普通记录。外部数据仍先安全校验并隔离复制，再进入内部表示；公开回调/快照还原普通表，不授予 skipValidation 权限。

字符和分类的 posting 集合压成单值/密集数组，集合操作集中管理；增删只影响相关集合，不全量重建。必须对照测试字面、多词、中文、模糊候选、排序、过滤、增量与身份；有界模糊候选的遍历变化不能被当作等价默默放过。

无新增 timer、轮询、运行时 GC、UI、磁盘缓存或 Provider 特例。当前 source/recordKey 和业务代次继续负责身份，关闭/注销继续按原路径取消与释放。内部布局只在 Storage 维护，新增公开字段仍经 Boundary/SDK 语义设计；payload 保持普通扩展对象。

固定 2689 目录基线约 6888.7 KiB；目标低于 5632 KiB，48 查询分配保持 4096 KiB 以内、增长512 KiB以内。前后固定查询至少7轮交替测量；热查询中位数目标不超过基线1.15倍（低于计时分辨率时使用高精度64位离线计时），增量/重建成本单列，不把纯表示原型当作完整产品收益。原有安全、业务与生命周期门禁不放宽。实机内存/视觉/战斗另行待验证。

## 最终接口与取舍

Storage 提供 PackRecord、Entry、Copy、Equal、Fields、SearchFields 与 posting Add/Remove/Has。常用记录字段一组密集槽位；稀疏合法字段保留具名键。元表在 Host 低频具名读取处复用，热循环从同一份 EntrySlots 布局取得局部常量，消除每次比较的元方法调用。布局没有散落到 Provider、UI 或公开 SDK；无需代理对象、常驻普通副本或每行元表。

Provider/Index 仍共享唯一 canonical 身份，原子提交完成后 Provider 才接纳 Index 中的记录。Copy 按语义字段恢复普通表；External Boundary 仍先安全检查再隔离复制，不能拿数字布局绕过验证。SDK 新业务数据放 payload；新增顶层字段仍按版本契约由 Boundary 定义。Storage 能往返未来稀疏字段不代表 SDK 接受任意顶层属性。

posting 采用 nil / 单字符串 / 排序密集数组，二分判重/定位，插入删除只移动该 posting 的后缀；不是 O(1) 更新。字符集合选择最小集合后检查交集；直接来自最小集合的候选不再重复检查同一集合。全局 entries/source.entryKeys 保留必要按ID查找，不叠加另一套重复编号映射或永久集合缓存。

**明确行为修订**：当错拼产生的候选超过 fuzzyLimit，旧实现按 Lua 哈希遍历顺序选取，结果可能随构建和哈希状态变化；现在按记录键稳定选取。此处不宣称所有错拼结果与旧版完全相同。字面、短词规则、中文、多词、TopK 权重、动作与过滤保持；模糊上限和时间预算保持，稳定顺序跨重建/禁用恢复/输入顺序通过独立场景验收。

第一版元表热访问使120次查询中位增加约21%，因此未交付；改为引擎局部槽位访问后，七轮交替高精度对照恢复接近基线。收益、最终数据与未实机场景见验证记录。公开 SDK 仍为2/revision6，UI Runtime1，搜索存档导出仍为具名 schema1，不持久化槽位布局。

最终数据、构建/更新代价和实机待验证项见 [验收记录](../validation/2026-09-12-compact-search/RESULTS.md)。非搜索字段更新复用已编译字段；批量启用/重建按记录键顺序插入、禁用反序移除。实际使用的索引仅保留 grams/categories，删除旧 exact/prefix/tokens 空容器。
