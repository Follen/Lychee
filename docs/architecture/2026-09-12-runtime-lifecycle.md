# 角色设置与可预测内存：实施设计

2026-09-12。用户最新决策：设置按角色独立；所有自带 Provider 默认开启（包括 EUI、EX）；在功能、交互和搜索体验一致的前提下尽可能降低内存，不再要求低于 1 MiB。允许 SDK 破坏式更新不意味着必须破坏协议。本轮保留 Provider API 2 / revision 6 与 UI Runtime 1，改进内部所有权。

## 依据与选择

[完整实机基准](../validation/2026-09-12-search-rebuild/RUNTIME_RESULTS.md) `LYCHEE-PERF-1789203670` 全部基准通过。成就无缓存重扫约 3.7 秒、缓存恢复约 13ms；保留成就后完整私有重建仍约 534ms。当前目录已经由 Provider 与索引共享，不能假设还有一整份重复记录可删。首领和坐骑的重复安全遍历是主要 CPU 热点；展开的小型动作/类别表、账号多角色缓存和隐藏 UI 绑定是保留优化目标。

因此采用**紧凑常驻权威数据 + 单次受控接收 + 可释放活动引用**。本轮不引入 LoD 伴随包、全量休眠/睡醒重建、SDK 3 或新的 TTL。保留快速完整查询，不把半秒恢复推给用户，不强制 GC。旧 1 MiB 探索保存在 [历史提案](2026-09-12-one-mib-exploration.md)，不是实现合同。

## 一个角色存储入口

`Core/CharacterStore.lua` 在 Bootstrap 后加载，集中提供当前角色 root、palette、disabledProviders 和一次性迁移。它不在文件加载期捕获或初始化 SV root；WoW 恢复存档后，登录入口初始化当前角色，读取方法也始终使用当前 root。

- `LycheeCharacterDB.palette`：面板、减少动态效果、最近使用、搜索模式、前缀、别名和选择记忆。
- `LycheeCharacterDB.pinned`：原有角色固定列表，保持顺序、删除和撤销语义。
- `LycheeCharacterDB.disabledProviders`：当前角色显式关闭的来源；缺省即开启，宿主内置设置来源仍不可关闭。
- `LycheeCharacterDB.defaultBindingAttempted`：当前角色的首次默认快捷键尝试；仍尊重 WoW 当前键位集和已有键位，不强制改为角色键位集。
- `LycheeCharacterDB.achievementCatalog`：当前角色的紧凑成就权威缓存。

旧账号面板设置只在升级角色首次初始化时转移一次，已有角色字段优先，旧账号固定不导入。后续角色从各自默认值开始。旧账号禁用标记混合自动默认关闭与用户选择，不能推断每个角色意愿，故不继承为新角色默认；已存在的角色关闭选择始终保留。用户固定、历史与别名不因内存优化清空。

此 module 的 interface 隐藏 SV root 恢复时序和迁移；生产 WoW 恢复与测试角色 root 替换是两个 adapter。删除它会将相同的时序判断重新散落到 Registry、UI、搜索和目录，因而具备实际 depth、locality 与 leverage。

## 成就：一份权威缓存

schema 4 为当前角色的 `ids/texts/categories/counts/key/builtAt/bytes`，平行数组只保存搜索需要的目录信息。活动搜索直接使用这些私有数组，派生的 ID→位置映射按启用创建、禁用释放。查询结果、进度与动作仍通过实时 API 单独生成，不把可变缓存数组交给 SDK 调用方。

首次有效旧 schema 3 缓存只提取当前角色（包含差异与增量覆盖），通过校验后转为 schema 4；账号内其他角色的可再生缓存不再常驻，各角色以后使用自己的 SV。损坏、版本/语言/角色不符或超过七天的缓存沿用重建规则，分类数量变化只读取变化分类。

`ACHIEVEMENT_EARNED` 继续按 ID 及关联成就增量更新；战斗只积累有限待处理 ID，脱战恢复。关闭面板不禁用来源事件，也不清成就权威数据；用户禁用来源则取消查询、任务和订阅，保留可恢复的角色缓存。没有新增轮询。

## SDK 的单次接收与所有权

`Boundary` 承担访问性/secret/循环/metatable/深度/数量校验及隔离复制；`ProviderRuntime` 负责本地化、动作展开、最终记录语义；Registry 消费同时具备 Host 所有权与一次性校验凭据的批次，避免再次遍历已验证的同一张图。无凭据的输入仍完整验证。凭据不通过公开字段或 SDK 选项传入，失败、注销、重入与迟到回调仍按原有事务和代次处理。

只共享 Host 私有且值相同的小型展示元数据：短 aliases/keywords/category 使用每 Provider 有界弱值池（至多 128 个、key≤256 字节）；已声明普通动作可复用其描述和单动作列表。payload、受保护动作与公开回调快照不参与通用池。键和值及淘汰结构全部有界，大值正常处理但不缓存。外部修改不能影响已提交记录或其他记录。

这是内部接收 seam 的加深，公开 SDK 仍保持原来的数据、失败和生命周期契约。校验优化必须同时通过伪造凭据、secret、循环、可变输入、共享碰撞、过量元数据、事务失败和同步重入测试。
