# Provider SDK 1.0.0 与五包生命周期重构

状态：实施中，已有搬移是未完成工作，未提交、未同步。分支 `codex/provider-sdk-1.0.0`；业务基线 `050111d`。本文件描述已确认目标，未勾选项不代表已经实现。

## 已确认约束

- SDK发行版本1.0.0；新协议API3/revision1，直接拒绝API2及完整目录注册，不提供旧接口兼容桥。
- 全部来源包括荔枝自己的Provider在其端计算匹配；Host仅调度、校验少量结果、合并排序、显示与分发动作。可选匹配/评分/目录工具属于Provider，不强制第三方使用。
- 第三方自己控制适配子插件加载；一个子插件允许多个独立Provider。荔枝不发现或管理第三方子插件。嵌入SDK无Host时正常降级，多个SDK实例不互相覆盖。
- Lychee为纯Host，不承载游戏业务Provider。Lychee_Player承载11个Provider：技能、背包、天赋方案、装备方案、坐骑、成就、菜单、暴雪设置、纹章、宏伟宝库、钥匙；Encounters承载团本首领和大米助手；Integrations承载EUI和EX；Inspector承载插件识别。保留16个独立功能身份与开关。
- 所有现行源码/注释/文档采用Provider语义，机器ID lychee.*。源码直接按加载包组织，不保留Builtin或Providers总目录。当前用户要求覆盖此前保留builtin.*命名的方案；一次性数据迁移保留角色开关、固定项、历史、别名和来源配置，不重新解释用户意图。
- Host只向已注册Provider发查询，不通过输入猜业务来源、不发现或加载第三方插件。荔枝各功能包负责其注册及内部加载；已注册的延迟Provider必须准备好后接续当前最新查询，取消/关闭/战斗不复活。普通搜索不能因延迟准备少查已启用来源。已加载AddOn不能卸载，使用后成本按全部包总和报告。
- 成就缓存迁出主包SV，未加载期间发生的变化在首次使用补齐；钥匙必要通信保留；EUI注册捕获必须早于不可补读的注册，不通过建UI补索引。
- UI、模型、开关动画、原有安全点击/拖动及交互不改。更新SDK、架构、设计、i18n、性能、交付、工具与测试文档，历史记录标历史，不冒充现行规则。

## 验收口径

搜索覆盖、集合、排名、可见文字、命中证据和动作参数分别核对；异步结果按最终最新查询验收，不能用旧接口测试适配层掩盖Host仍接收目录。固定项只存稳定引用。新匹配工具可独立替换，Host不读取Provider内部目录。

旧整体预算不靠统计迁移、默认关闭功能、少查数据、强制GC或临时放宽阈值满足。分别报告未使用、冷启动查询、热查询、关闭及全部功能使用后的模块合计Lua堆/临时分配/活动资源，纹理和模型引擎内存另报。旧数据身份迁移是存档升级，不是兼容旧SDK。

## 最终源码组织（用户最新确认）

- `addon/Lychee`：Core、Search调度、PublicAPI、Secure、UI，以及框架自身资源；不包含GameMenus、BlizzardSettings、Crests、GreatVault、Keystones或其他业务目录。
- `addon/Lychee_Player`：PlayerSpells、Bags、TalentLoadouts、EquipmentSets、Mounts、Achievements、GameMenus、BlizzardSettings、Crests、GreatVault、Keystones。
- `addon/Lychee_Encounters`：Bosses、LDT。
- `addon/Lychee_Integrations`：Ellesmere、Exwind。
- `addon/Lychee_Inspector`：识别Provider、Picker和View直接放包内。

包名用于加载/发布；Provider仍独立注册、开关和资源归属。每个功能包使用自身的WoW私有namespace，不把所有业务继续塞入Host的I.Modules；通过同一SDK契约与Host协作。没有新的Providers总目录；公共SDK工具不属于任何单个业务Provider。

## 纯Host职责与加载修订

Host只维护Provider注册信息、查询代次与调度、有限结果合并排序、通用UI/动作安全、角色偏好及稳定引用。Host不拥有业务数据、业务事件、具体Provider清单或跨包模块容器；不认识钥匙、成就、EUI等实现。自己的设置页属于框架UI，不伪装成游戏业务来源。

各功能包独立注册自己的多个Provider，通过SDK获得注册/查询/资源能力。共享匹配/评分/分批/目录工具由SDK维护，各Provider可选用；Host不参与各家的目录检索。只对实际跨包复用的框架工具设Shared，不重新创建类似Builtin/Providers的业务总目录。

Player的启动生命周期由后台业务决定：启用钥匙时按原时序启动LibKS通信、队伍事件和必要状态；其他功能分别定义事件、数据和UI初始化时机。禁用钥匙只停钥匙，不停其他10个Provider。EUI同理，捕获不可补读注册所必需的代码必须及时就绪，不能用延迟注册牺牲搜索覆盖。

必须区分三种成本：AddOn的Lua代码加载、Provider业务数据准备、UI创建。整包按需加载适用于允许整包延迟的职责，不能自动套给Player。一个已加载AddOn的TOC文件和声明SV会进入内存，普通Lua工厂只能延迟执行/建表，不能让这些文件重新变成未加载。

因此当前先确定五个功能包与纯Host的职责，不再承诺四个功能包全部是真正LoadOnDemand。若坚持只有这五个AddOn，Player需按需初始化数据/UI，但其Lua与声明SV加载成本必须如实计入。成就大型缓存即使移到Player的SV，也不会仅因换归属而避免登录加载。若后续测量要求大型缓存真正延迟进入内存，需要额外由Player自己管理的LoadOnDemand数据AddOn；这是新增加载单位，须在最终包清单中明示，不能称作仍只有五包或偷偷把缓存塞给无关包。

用户已授权按新职责实施，不按旧的“主包保留五种游戏功能”方案交付。全部功能业务等价、SDK旧接口拒绝、现行文档/注释统一、角色数据身份迁移与模块合计性能验收约束不变。

## 子插件数据所有权（已纳入实施）

Host DB 仅持久化框架设置、Provider 稳定 ID 对应的用户开关与搜索覆盖，以及固定项、历史、别名、搜索记忆所需的有界稳定引用和显示回退。Provider 目录、内部设置、业务缓存、包实现、回调和运行状态不写入 Host DB。

各功能包声明并拥有自身 SavedVariables；SDK 存储工厂接收该包的存储根访问器，不能自己读取 Host CharacterStore，也不能在文件加载时提前捕获尚未恢复的 SV 表。当前业务设置默认按角色；账号共享仅用于明确允许跨角色共享的独立数据，不能悄悄提升设置作用域。同包多个 Provider 使用独立命名空间与 schema 版本；一个 Provider 损坏或迁移失败不能覆盖兄弟 Provider 的数据。

SDK 提供有界读取/写入、复制隔离、schema 校验和显式迁移流程。普通设置沿用既有容量门禁；大型成就缓存使用 Player 自有的专用 schema 和原容量上限，不通过放大通用 Settings 限额塞入。缓存与设置分开：设置不能自动淘汰；可重建缓存必须定义语言、客户端、角色、版本、失效与重建时机。查询临时缓存归 query 作用域，不持久化。

迁移前验证旧数据，构造并验证目标，目标成功提交后再定向移除旧字段；失败保持原文并报告，不静默重置。一次性从 Host 迁出的仅是有明确所属来源的数据，包括现有 providerSettings 与 achievementCatalog，Host 不留下业务副本。该读取通道只用于存档升级，不恢复旧 SDK 接口。卸载/注销 Provider 保留其已有用户数据，不顺带执行破坏性清理。

Player 的 DB 可以命名为 LycheePlayerCharacterDB，其他包使用各自名称；没有实际持久化需求的包不预建空 DB。第三方可绑定它原有 DB，不要求使用荔枝前缀或重建数据库。关闭功能不等于卸载已经读入的 SV，内存按所有包合计核算。

验收必须覆盖角色隔离、同包多 Provider 隔离、迟到恢复与存储根替换、迁移失败原文保留、重新注册恢复、坏数据/大数据边界、版本前进与未知新版本拒写、查询结束释放临时缓存，以及 Host DB 中没有新增 Provider 业务数据。

## Provider 管理页交互方案

用户任务是理解当前有哪些已接入功能，并分别控制当前角色的启用与搜索设置。延续 DESIGN.md 的近黑底、暖白文字、红色状态和现有扁平图标；这是管理界面，优先保证状态可理解和操作位置稳定。

### 注册、偏好、运行状态分开

- 管理页只列当前成功注册且尚未注销的 Provider。Host 不扫描插件目录、不硬编码荔枝功能名单，也不通过旧存档伪造尚未接入的功能行。
- 注册只提交有界的说明、来源包身份和能力回调；不等于建立完整目录、创建 UI 或启动业务事件。延迟准备由注册后的 Provider 自己负责，不额外建立一套声明注册表。
- 用户关闭是停用，不是注销：保留注册信息和行，停止该 Provider 的查询、后台业务和可取消资源。重新开启仍有入口，其他同包 Provider 不受影响。协议要求所有者不得为了响应普通停用而注销自己；永久退出才注销。
- 开关读写当前角色的启用偏好，不直接代表实时可用性。已开启但缺依赖、准备失败或等待条件的 Provider 必须明确显示原因；用户仍可关闭它，也可预先保存开启偏好，不能假装已启动。
- 注销后从列表移除，但保留既有角色配置和稳定引用。重新注册同一稳定 ID 恢复偏好；没有历史偏好时应用声明默认值。只保留本来需要的设置，不新增历次来源名称、图标或能力目录缓存。
- 真正未加载且从未注册的整个包无法在此出现。需要可发现的功能由所属包及时完成轻量注册；其启动代码成本如实计入总量。Host 不通过打开管理页强制加载全部功能。

| 情况 | 管理行 | 开关与反馈 |
| --- | --- | --- |
| 已注册、用户开启、可用 | 显示 | 开启；按需准备的数据不因此提前建立 |
| 已注册、用户关闭 | 保留 | 关闭；可再次开启 |
| 已注册、用户开启、暂不可用 | 保留 | 开启；说明缺失依赖或具体等待原因 |
| 当前查询正在准备 | 保留 | 保持偏好；局部显示准备状态，不因绘制行启动准备 |
| 已注销或从未注册 | 不显示 | 无开关，不推断已卸载或依赖缺失 |
| 注册被新协议拒绝 | 不作为成功注册行显示 | SDK 返回明确错误，走有界诊断；不开旧接口兼容通道 |

### 布局与操作

- 页面名称为“功能来源”，按用户要求不显示“仅影响当前角色”的提示，角色隔离行为保持。移除“内置／第三方”和基于具体 Provider ID 的固定排序表。
- 按实际注册的来源包身份分组，展示本地化包名。荔枝的包可显示为“玩家功能”“副本资料”“插件集成”“插件识别”，文字由包声明；第三方同样声明自己的名称。分组用稳定身份，不能按翻译后的名字合并；缺少展示名回退真实所属 AddOn 名，不推断业务类别。
- 分组只负责浏览，不新增包级总开关，避免两层开关互相遮盖。分组及行顺序不随开启、关闭、准备或失败状态跳动。
- 每行左侧保留统一风格图标，中间为名称和一行说明，右侧固定为设置入口和开关。将重复的“点击管理”收敛为“设置”或公共设置图标，完整提示和键盘操作保持可发现；功能说明不因关闭而整体暗到难以阅读。
- 正常行不堆叠“已注册／已启用”等标签；异常时在说明位置显示具体原因，详情保留功能介绍。开关只使用现有强调色，原因同时用文字表达，不能只靠颜色。
- 行主体进入来源设置；开关点击只改偏好，不同时导航。既有全局搜索、前缀、关键词等设置保持业务语义；不会把启用开关缩窄为“只参与搜索”，钥匙等后台功能也受停用约束。
- 无来源时显示“暂无已接入的功能来源”，说明需要启用提供功能的插件；不声称检测到某插件未安装。注销发生在详情页时回到列表并给出一次提示，保留配置，不继续操作过期实例。

### SDK 与验收约束

统一 SDK 契约提供来源包元信息、独立 Provider 身份、角色启停生命周期和有界可用状态通知；Host 组合展示状态并管理偏好，包报告业务就绪及原因。业务回调、目录与实例不持久化到 SV。

注册、注销、偏好和可用状态变化触发管理页失效，页面隐藏时不维护第二份展示列表；再次打开读取当前快照。继续复用可见行和现有池，不添加轮询、全量预热或逐行定时器。

验收补入 SDK 契约和管理页回归：关闭后行仍在且资源停止；同包多 Provider 独立；缺依赖时偏好不丢；重新注册恢复角色设置；迟到回调不能改新实例；详情页注销；按下后行重绑再松开；无来源和全部关闭；加载前后及中英文分组；旧协议拒绝；1000 来源下沿用现有虚拟列表和分配门禁。具体预算继续以 PERFORMANCE.md 为唯一来源。基础管理模型、UI 与包级声明已通过离线完整测试；客户端观感需重启后实机确认。

## 2026-09-13 实施结果

五包真实 TOC/私有命名空间、API 3 统一候选回复、Provider 自有目录、Player 角色设置和成就存档均已落地；SDK 1.0.0 类型、示例、协议、独立存储、公开能力边界及生成合同同步完成。Host 不再包含业务 Modules、业务词典或识别页工厂。

公开 SDK 不包含 InitializePackage/InitializeCatalogRuntime，不要求 Modules/Definitions/Presentation。相同目录工具仅在包内复用，界面动作保留各自语言归属；Storage 嵌入副本按字节与开发包保持一致。

已完成完整契约检查：业务等价、角色迁移、四客户端×双语言、真实 ADDON_LOADED/登录顺序、原性能门禁、公开 SDK 原始输入与失效行为、文件交付反向测试。详情见 [最终验证记录](../validation/2026-09-13-provider-sdk-1.0.0.md)。

游戏冷启动、实际模型和动效观感尚未在新五包结构下实机确认；需完全退出并重启客户端。不能把离线加载数字当作游戏整体常驻读数，不能把旧录像或旧运行报告当成本轮验证。
