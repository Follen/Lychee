# 文档维护

## 放在哪里

| 内容 | 位置 |
| --- | --- |
| 玩家安装、使用和介绍 | 根 README.md / README.en.md |
| 当前项目开发和交付步骤 | docs/guides，入口为 docs/README.md |
| 当前公共 SDK | lychee-sdk/README.md / README.en.md；专题分别在 docs/zh-CN 和 docs/en |
| 可运行示例或集成片段 | lychee-sdk/examples，双语索引说明能否独立安装 |
| 历史设计 | docs/archive/design |
| 历史验收与原始输出 | docs/archive/validation；报告与对应证据放在一起 |
| Comet 工作流资料 | docs/comet，由对应工作流维护，不混入现行 SDK |

根目录的 DESIGN、PERFORMANCE、i18n 等保留为共同规范入口，不复制到各开发指南。历史报告不是新的执行指令，也不自动成为当前版本验收。

## 中英文同步

SDK 每个专题在两种语言下使用相同文件名，页面顶部提供目录和对应语言链接。中文首页和英文首页按同一组任务导航，英文首页不能把读者无提示地送回中文协议。只翻译说明和显示示例；标识、字段、错误码、容量、参数顺序与生命周期必须一致。

中文 PERFORMANCE 是根规范的生成副本；英文 PERFORMANCE 是 SDK 接入性能指南，明确链接完整政策，不能自定不同预算。项目内部指南和历史日志可保持原始语言，由入口标明，不制造空白翻译页。修改公共语义时同轮更新相关双语页面、示例、类型与测试。

删除已退役接口内容时，不把旧测量改写为新版本通过；需要完整原文从 Git 历史读取。搬移文档同步重写本地链接、源码路径、构建清单和索引，不保留两份正文。

## 检查与交付

运行 `python tools/check_repository.py`，核对现行文档链接、锚点、源码路径、版本、中英文配对及 SDK 内部链接闭包。所有 SDK 文件必须列入 tools/sdk_contract.json，并通过 `python tools/build_sdk.py --check`。SDK ZIP 包含两种语言；游戏 ZIP 仅含运行资源与许可证。

文档检查不能证明文字语义正确。人工核对字段、边界、示例、实际命令和验收范围；跨语言改动重点检查否定、单位、默认值、取消与失败语义。检查通过后再提交和构建产物。
