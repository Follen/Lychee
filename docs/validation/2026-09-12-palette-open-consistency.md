# 加强双向动效与重复打开一致性

用户再次明确要求打开、关闭均具有明显动画感，并报告 reload 后首次打开比后续打开明显。基线 d3141a3。

## 调查结论与复现范围

代码未发现首次专用动画或缓存后主动缩短动画的分支。既有开场采用快速衰减曲线，空间幅度 8%，主体运动集中在前段；这与用户想要的明显展开不符。

此外，驱动直接累计 OnUpdate 的 elapsed，没有每次播放的独立时钟。以可控精确时钟模拟“隐藏十秒后恢复，但新动画实际只运行 16 ms”的场景，旧实现因偏大的首帧 elapsed 直接结束；新增断言 `warm opening must not consume time spent hidden` 在旧实现失败。此故障注入证明旧实现存在计时脆弱点，**不证明当前 WoW 客户端正常恢复时一定传入隐藏时长，也不据此认定它是用户实机现象的唯一根因**。

## 最终行为与成本预算

- 打开：380 ms，真实尺寸 84%→100%，从下方 24 逻辑像素浮起。完整开场初速度为 2/时长，Hermite 曲线柔和停稳；透明度在位置/0.35 上做 smoothstep。
- 关闭：320 ms，真实尺寸收回 84%，退回下方 24 逻辑像素，末段消隐。途中改向保留当前位移与速度；最后回到准确尺寸/位置。
- 使用 GetTimePreciseSec 的本次播放起点计时，每次完整关闭后的打开重新建立时钟和初始状态；最小接口替身保留 elapsed 降级路径。未结束的反向操作继续当前位置与速度，不与完整关闭后的新开场混同。
- 更新仍只由原有一个短时驱动执行；不新增 Frame、事件、timer、动画组或缓存。最长活动预算从 300/280 ms 改为 380/320 ms，以满足用户明确要求的双向可感知动效。每帧只增加一次精确时钟读取，其余为标量计算与变化检查。
- 输入不等待动画完成。真实几何与安全按钮命中区域同步，战斗立即停止受保护修改并隐藏，脱战不重开；减少动态效果即时复位。完整关闭时清除目标、布局、回调和时钟引用。

## 验证

- `tests/ui_motion.lua`：12 次完整关闭/等待/打开，每次采样 16、60、120、200、300、400 ms，比较尺寸、透明度和顶边位置，全部一致。首帧注入偏大 elapsed 不跳过新开场。
- 保留完整轨迹的 30/120 Hz 对照、反向速度、重复关闭、末端连续性、减少动态效果、战斗抢占和 setter 重入检查。
- 1000 轮反向及按 120 Hz 完整播放开关：179.69 KiB 累计分配，本轮替身 CPU 67 ms，暖 Frame/动画组增长 0，结束无活动更新和目标引用。预算仍为累计分配 <512 KiB；不将替身耗时解释为游戏布局或 FPS。
- `tests/interaction_smoke.lua` 保留真实 Palette 的失焦 Esc、安全战斗关闭、输入和 Provider 生命周期验证。
- 完整回归入口 `tests/check_contract.ps1`，日志 `%TEMP%/lychee-palette-open-consistency-check.log`；wowdoc 77 Lua 校验及 diff 检查随交付执行。
