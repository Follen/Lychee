# LDT 搜索临时分配修复

用户在搜索／打开LDT后报告荔枝38.14 MB。该截图不能单独证明泄漏，尚缺同场景关闭及回收后实机读数。

## 修复前证据与目标

基线提交a3e38ae，Lua5.1，tests/ldt_provider.lua相同20次混合查询：累计15841.5 KiB，回收后增长0.9 KiB。仅离线测量；不等于客户端归因内存。

隔离计量：LoadDungeon调用480次，分配13174.2 KiB；Aliases调用13880次，分配1982.5 KiB；Normalize调用190880次，分配97.0 KiB。查询重复展开完整副本资料是主要分配源。

修复前保存44组双语言完整业务结果、顺序、别名和动作参数作为独立对照。计划将数据模块收敛为借用具名搜索记录的流式遍历与按NPC创建详情；临时记录归当前查询所有，可跨该查询协程让出，不得被候选或其他查询持有。候选入选时复制必要字段，至多20条；完整怪物对象只在详情/恢复时创建。不新增跨查询缓存、空闲任务或GC调用。

修复目标：原20次查询累计分配<4096 KiB，保留增长<128 KiB；新增模块加载仍<512 KiB，总TOC仍<1858 KiB。继续测量CPU、单批时间、取消后迟到事件及业务等价。SDK公开具名记录协议不变。

WoW接口未变化；核对wow-ui-source / retail / latest，resolvedCommit 8ea15b61e45c0ed4eba01439c90757f86eb78d34，C_Spell.GetSpellName证据沿用首次实现记录并重新inspect。source check显示本地与远端一致。

## 同输入前后结果

使用相同真实SDK装配与44组对照预热；旧数据模块和Catalog从a3e38ae读取，仅在离线dofile边界替换，其他代码、输入和C_Spell替身相同。原20次混合序列各跑三轮，测量区间停GC，结束恢复并回收。

累计分配约下降92.6%；CPU中位数相同，不宣称提速。固定代码约增加99.1 KiB，换掉反复创建整库对象树，不是引入跨查询缓存。全TOC离线回收后1680.0 KiB，仍低于1858预算。此处报告累计分配，不等同游戏内峰值或截图读数降幅。

硬回归：44组双语言旧结果逐字段对比；462怪物全部详情、1539技能ID关系与独立JSON逐项核对；挂起扫描取消后弱引用回收；异步/同步加载、迟到事件和20次UI复用沿用原测试。4MiB门禁替代原32MiB门禁，加载和保留门禁不放宽。完整检查结果及游戏内复测需分别记录。
