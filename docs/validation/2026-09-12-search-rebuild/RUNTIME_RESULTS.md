## 5. UI、隔离与清理

旧第二份实际三次调用生产控制器 Show/Hide，初始已创建；每次 shown=true、header/content alpha=1、行池=8、rect约 (640,450,640,390)，最终 closed=true、geometryStable=true。Show 调用 2.064 / 1.329 / 1.198ms，Hide 调用 1.051 / 1.007 / 1.088ms，均不含整个动画时间。第一关闭后 0.05 秒快速重开被包含，但没有硬件 Alt+Space/Esc、全部页面或视觉质量验证。

新版不存在 `ui`、`liveAfter`、`userStateAfter` 或 `userCharacterStateUnchanged`：流程未到达，不是失败，也不是通过。`cleanupOK=true` 证明私有 release 的来源/索引/jobs 检查成功；`upstreamCleanupOK=true`、准备阶段 closed/registrationRestored=true 证明该正常设置准备的清理路径成功。`liveRootsUnchanged=true` 只检查生产根对象身份，不能证明其内容完全不变。

旧第二份生产 live 记录从 1989/version78 到 1990/version83；根与角色用户状态比对通过，仍不可称作完整生产目录不变。新报告缺最终用户状态比对，不借用旧报告结论。报告之间无严格相同的后台工作控制，不报告前后优化百分比。

## 6. 对最终方案的约束

1. **P0 先验证固定下限。** 分别测首次未用与完整使用后的产品全包固定根。没有固定下限的具体缩减证据，不开始以 1MiB 已可达为前提的全面改写。
2. **合并接收校验与紧凑表示优先。** 首领的小表/字段与重复 SDK 遍历是有实测依据的热点；保留非法输入、外部修改隔离、原子提交和完整业务参照，不能关闭校验换速度。
3. **按恢复成本决定保留。** 成就重新采集约 4 秒，不能每次清掉就重扫；比较有版本的紧凑权威缓存、共享静态字典及真实总字节。技能/背包/坐骑读取较轻，休眠只保留有界失效状态，恢复读取最新数据。最终缓存预算尚未确定。
4. **生命周期管理活动数据。** SDK 3 轻声明、活动实例、查询资源与 UI 池分离；温态保留只改善短时间重开，不能替代睡醒后的完整结果延迟验收。原生 UI 保留结构、清绑定，不重建 Frame 或修改已确认动效。
5. **真实集成单独证明恢复。** EUI 已捕获设置项不能丢，EX 声明读取不等于执行路径已验证；同 ID、标签、排序、参数和动作权限对照。SDK 破坏式升级不允许减少业务内容达标。
6. **测试框架先能报不完整。** 超时、来源错误、状态提示、实际 UI 缺失及最终采样缺失必须可见。三份报告足以指导实验方向，不足以通过 P0，更不是整体运行时升级验收。

后续正式实现按用户决定在新分支进行。本轮仅归档数据和补强设计，不改生产运行时、不清用户存档、不追加游戏操作。
