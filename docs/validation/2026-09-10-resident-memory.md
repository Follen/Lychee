# 启动常驻内存压缩

用户报告 `/reload` 后稳定在十多 MB。本轮基线 `2ac3924`，只调整搜索编译结构，不减少来源、记录、别名或搜索能力，不把初始化转移到首次输入，也不增加强制 GC。

## 归因与设计

在原有 2,689 条固定目录中，6,272 个编译字段及其容器在离线破坏性归因中释放约 1,163 KiB。旧结构为每个字段单建一张含 field/text/normalized 的散列表；新结构在每条记录唯一的 fields 数组内保存连续三元组：字段类型、原始文字、规范化文字。评分、匹配文字、权重、字段平分时的顺序、字符倒排与公开返回结构保持不变。

所有者仍是索引记录；容量随已经接受的记录及字段总量增长，没有额外缓存或历史保留。更新仅重建变化记录，禁用/注销释放编译结构，恢复重建。无新增 Frame、事件、timer、每帧活动或战斗扫描。查询循环按三个槽位步进，不生成临时字段表。公开 Provider 记录及动作参数复制隔离保持原样。

最初提出至少降低 15% 的探索目标；归因表明整个字段结构仅占约 15%，无法通过压缩全部消除，因此在实施前撤回该预测。固定普通场景最终验收门槛从 9 MiB 收紧到 7.25 MiB（7,424 KiB），为当前约 7,146 KiB 留出约 278 KiB 运行环境余量；查询分配与保留增长门槛不变。旧实现已实际触发新门槛失败。

## 同输入对照

Windows Lua 5.1；固定前后实现，各五轮交替运行普通目录、扩展技能目录、禁用/恢复场景。完整回收后记录保留内存；预热后在暂停 GC 的固定 48 次查询区间记录累计分配，随后恢复 GC。原始输出见 [测量记录](../architecture/2026-09-10-resident-memory-measurements.json)。基线加载路径适配约有 1.6 KiB 固定开销；不影响主要收益结论，不能把它计为压缩收益。

| 离线场景 | 基线 KiB | 修改后 KiB |
| --- | ---: | ---: |
| 2,689 条目录回收后保留 | 7,833.8 | 7,145.6 |
| 3,689 条扩展目录回收后保留 | 10,590.9 | 9,527.7 |
| 禁用坐骑来源后 | 7,310.5 | 6,786.4 |
| 恢复坐骑来源后 | 7,840.3 | 7,152.2 |

普通目录约减少 8.8%，扩展目录约减少 10%；不声称已把客户端十多 MB 降到这里的离线数字。毫秒级查询样本接近计时器分辨率，不据此宣称 CPU 或帧率提高。
