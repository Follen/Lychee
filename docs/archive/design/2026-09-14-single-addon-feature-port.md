# 基于单插件版的功能与 SDK 迁移方案

状态：实施中（2026-09-14）。用户已授权在本分支迁入用户功能、SDK 和后续 UI 优化；实机验收通过前不宣称完成。新版参照分支现名 `Lychee-multi-addons`。

## 1. 起点与目标

- 新分支：`codex/single-addon-feature-port`。
- 起点：最后一个单插件版本 `050111dbdf4a5ee71d4de281e7115339ab820f44`。
- 功能参照：新版 `f715f0a`；其最近运行代码修改是 `a66df90275fc838bfe118d4b5ff4a8c842061ed8`。
- 新工作树：`D:/Code/wow/worktrees/Lychee-single-addon-feature-port`。
- 新版工作树：`D:/Code/wow/worktrees/Lychee-unified-provider-lifecycle`，继续保留。
- 历史基线工作树：`D:/Code/wow/worktrees/Lychee-single-addon-baseline`，保持原样，不能作为实施目录。

目标是以旧版的搜索和数据路径为基础，迁入新版实际新增的用户功能及有价值的公开 SDK 能力。保持旧版已有业务范围，恢复快速首批结果，控制新增成本。不能把新版整个 Host、生命周期和目录实现复制回来后称为基于旧版优化。

本方案默认保留一个自带功能发行包；第三方仍可独立安装、声明、加载和管理自己的数据。自带功能的逻辑边界与物理包数分开处理，不以重新拆成十包作为完成条件。若实施发现某项确实需要独立运行包，必须列明业务原因、加载影响和测量代价，再更新方案。

## 3. 用户功能迁移清单

| 范围 | 旧版已有 | 本次处理 |
| --- | --- | --- |
| 技能、物品、坐骑、装备和天赋方案、成就 | 已有 | 保持召回、动作、固定、别名及客户端范围；逐项回归 |
| 团本首领及技能、大米怪物及技能、模型详情 | 已有 | 保持事实数据、难度和查询行为；不迁入未经证明有收益的缓存或预扫 |
| 小队钥匙、分数和传送 | 已有 | 保留业务；核对新版有效修复，搜索开关不停止必要通信 |
| EUI、Exwind、插件识别 | 已有 | 保留原能力，核对新版修复；不为索引执行上游真实控件构造 |
| 暴雪设置定位 | 已有 | 保留定位，新增对应设置条目内的参数动作 |
| 设置直接修改 | 新增 | 开关、绝对和相对数值、可用选项、颜色、恢复默认；按原生能力提供 |
| 音量 | 新增操作能力 | 五通道属于暴雪设置 Provider 的各设置条目，不能再单列音量来源 |
| 自然语言 | 新增解析能力 | 中英文设置句式、搜索别名、单位和有限中文数字；支持错误提示 |
| 内嵌调整页 | 新增 | 音量与适用数值／选项控件；保留暴雪要求点击“应用”的语义 |
| 具体动作的固定、别名和最近记录 | 新增 | 保存目标、动作和参数；恢复后仍是同一次操作含义 |
| 关于页及底部入口 | 新增 | 中英文内容、赞赏／联系浮窗、已确认可扫的二维码；中文献词原样保留 |
| Tooltip、菜单、详情、底栏排版 | 改进 | 按当前用户确认的呈现选择性迁入，不连带替换搜索和动画控制器 |

自然语言词表归设置业务模块维护，SDK 只提供通用参数与可选句式工具。非法值、否定句、歧义目标和多目标请求不得误执行默认动作。搜索和预览不写设置，用户执行后才修改。

主动作按具体设置类型选择：音量打开调整页，适用即时开关可直接切换，普通数值／选项可打开调整页，其余打开定位。右键列出该条目的附加动作，不能把每种操作展开成重复搜索行。带明确参数的搜索结果以该参数动作为主动作。

## 4. UI 尺寸单独处理

源码确认新版确实放大过，首次变更位于 `5747808`：

| 参数 | 旧版 | 新版 |
| --- | ---: | ---: |
| 主面板逻辑宽 | 640 | 640 |
| 基准整体缩放 | 1.0 | 1.15 |
| 底栏逻辑高度 | 32 | 56 |
| 最大逻辑高度 | 518 | 542 |

1.15 是文字、图标、布局和命中区的整体缩放；实际屏幕尺寸还受游戏 UI 缩放和小视口限制影响。新版部分文字角色也有单独字号调整，不能仅用 15% 概括所有变化。

用户尚未要求恢复小尺寸。本次默认保留新版已确认的视觉功能和尺寸意图，将整体缩放、底栏空间、Tooltip 字号列为独立迁移项，提供相同分辨率下的前后对照。不得把回到旧代码起点等同于用户要求 UI 缩小，也不为迁入 UI 整体复制新版 Palette。

必须覆盖 6→5→4→3→2→1 和反向结果数量、快速输入、中文输入法组合、关闭重开、长中英文标题、滚动和小视口。检查实际内容、目标高度、最终高度与命中位置，不能只检查动画计时结束。

## 5. SDK 保留的能力与边界

公开版本为 SDK 1.0.0 / Provider API 1.0.0。不把版本改名算成功能收益。

| 能力 | 实施要求 |
| --- | --- |
| 普通 Provider、目录、异步查询和动作 | 保留简单接入路径；不强迫小来源实现冷声明、预热、Invocation 或紧凑存储 |
| 加载前发现 | 第三方用自己的 TOC 声明 ID、来源、路由、依赖及客户端范围；Host 不硬编码第三方名字 |
| 按需加载和准备 | Host 按实际请求加载；Provider 负责自己的数据准备。就绪、查询和加载不混成一个状态 |
| Invocation | 目标、动作、参数分开；校验、准备、执行、结果和取消清晰；不把普通动作自动解释为参数动作 |
| 独立存储 | 第三方自有 TOC/SV 和存储实例；可选 Storage 模块不依赖 Host 业务 DB |
| 大目录接入 | 保留普通目录、自定义查询及可选 documents/readEntry；CompactStore 可选，不能强制每个来源迁移 |
| 生命周期 | 不参与搜索、关闭窗口、撤销可用性、注销、业务停止分别定义；异步迟到结果不能复活旧请求 |
| 多客户端 | 声明过滤、原生 TOC 和实际 API 可用性共同决定；文档声明支持不等于实机通过 |

Host 只负责通用发现、查询协调、排序、展示和动作调度，保存框架偏好及有界引用。Provider 负责事实数据、词表、业务动作、缓存失效和后台通信。Widget 只呈现状态及收集交互，不决定缓存和插件加载。

自带模块即便与 Host 同包，也不得依赖其他业务模块的私有表来完成接入。自己的业务数据保留在模块拥有的命名空间中，Host 通用层不得汇总业务数据库。第三方拥有独立 SV；“同包模块私有命名空间”不应在文档中被描述成原生独立插件。加载同一个原生包不能实现其中 Lua 文件的独立卸载。

预热默认不遍历加载全部第三方。明确前缀、分类和显式引用优先定位来源；参与全局搜索的冷来源需要在实际全局请求中提供可搜索信息，不能为了速度偷偷漏掉它们。准备工作由 Provider 自己决定，Host 只协调、限额和取消。关闭面板可以释放临时查询和数据，但已加载原生 AddOn 的 Lua/SV 不能因此真正卸载。

## 6. 首批结果与交互稳定

沿用旧版逐步返回的基础，不要求最快来源等待最慢来源。任何新机制先在原查询链上证明必要性，不新增一个全来源完成后才放行的总屏障。

1. 每次输入建立新查询身份，取消旧工作，拒绝迟到回调。
2. 当前查询已有结果就显示；尚未完成用轻量“搜索中”提示，不把有内容的面板清空成大块黑底。
3. 旧查询内容若暂作视觉过渡，必须明确为过渡态并解除旧动作；不能把旧结果算作当前查询首批响应。
4. 未交互时可更新排序。键盘导航或鼠标按下后，以完整条目／调用身份保留选择，不按行号转移操作。
5. 鼠标按下至松开期间绑定变化则取消该次执行。新增结果不得把另一个动作替换到用户已经按下的位置。
6. 若需要短时合并更新，必须有有界时间且不能依赖最慢来源；先量化成本再决定是否采用。
7. 零结果只能在查询结束后确认为无结果；部分失败、超时和仍在加载必须区分。

具体排序和合并方式先用离线输入序列及真实客户端验证，不预先承诺“永不移动任何行”与“始终即时全局排序”同时成立。

最近记录保留有界标题、图标和来源标题作为恢复显示；恢复中不可执行过期动作。Tooltip 不重复显示相同恢复状态。新版已复现的普通 TouchRecent 丢失显示字段问题必须形成回归测试；超时、缺来源、删除、成功恢复分别验收，不能把所有情况永久写成“正在恢复”。

## 8. 验收口径

### 功能

建立旧版已有功能与新版新增功能两张矩阵，逐项记录通过、失败、未验证及 Ticket。业务等价包括 ID、召回、难度、来源范围、主动作、右键、安全施放、拖动、固定、别名、最近使用及跨会话引用，不只比较结果数量。

使用 lychee-dev 做大改动的真实运行时功能覆盖：正常、无结果、非法输入、失败、取消、超时、重试、关闭重开、战斗和相关第三方交互。真实鼠标安全动作与原生设置应用不能用直接 Lua 调用全部代替。音量等实测保存原值并核对恢复。

中文和英文分别验收，尤其自然语言、原生设置名称、动作标签和长文本。正式服之外按实际影响补离线和实机矩阵；没有对应客户端时明确待验证，不宣称四客户端全通过。

### 性能

性能规则仍由 PERFORMANCE.md 唯一维护。实施 A 批需把用户后续已确认的政策同步到旧分支：静态内存由 Agent 按证据判断合理性，全部适用包强制计入，运行时功能测试和性能测试分开。不能恢复旧版过时的固定静态总量上限，也不能自动放宽其他既有预算。

- 用相同角色、客户端、语言、来源开关、目录规模、输入序列和可比存档分别测旧起点与每个迁移候选；第一次冷启动与热轮次分开。
- 分别记录首批当前查询结果、首个可交互结果、完整查询结束、单次回调峰值、真实帧表现及结果完整性。旧过渡内容不算首批。
- 首批目标恢复到旧版同量级。以现有约49 ms 热态中位数为参考，初步目标不超过70 ms；正式门槛在 A 批同场景复测后记录，不能事后按慢实现改值。P95、最大值和零结果耗时单列，不能只优化中位数。
- 完整查询不得依靠减少来源、静默截断、频繁 GC 或默认关闭功能提速。旧版五秒异常也要调查，不把旧版所有行为视为正确。
- 内存同时报告加载后、首开后、全量搜索后、自然关闭后及诊断 GC 后，全部适用包合计；区分观察工具、自有数据、索引、结果对象和 SV。
- 新增每项 SDK／功能分别记录保留和临时分配增量、必要性及是否有更简单方案。不能预先承诺包含新增能力后必定低于旧版10.77 MiB。
- 重复开关、取消、来源切换和多轮查询后，任务、事件、Frame 池与保留对象稳定。静态门槛改为审查不代表泄漏、持续增长和 CPU 超限可接受。

## 9. 存档、交付和文档

不静默把旧动作引用重定向成另一个操作。针对用户当前存档，交付前单独列出来源 ID、普通引用、Invocation、别名、角色设置与业务缓存的读取策略；不能直接拿新版本存档覆盖旧版文件。

用户数据先备份，转换只能依据明确身份；无法恢复的记录明确提示。可再生缓存与用户偏好分开处理，保留现有用户数据。首次迁移、失败保护、下一会话恢复及回退都要实测。

实施交付必须先完成相关检查、提交、记录 hash，再按清单同步并核对 SHA-256。方案制定时游戏是十包安装；2026-09-19 现场已只剩 Lychee Dev。交付时重新列清单：若存在旧自带包，退出客户端后优先备份隔离，并处理 TOC/SV 差异。不能复用过去针对另外两个目录的删除授权，不能直接覆盖后留下重复注册的运行包。

同步更新清单：README 中英文、PRODUCT、PROVIDER_FEATURES、ARCHITECTURE、PROJECT_STRUCTURE、DEVELOPMENT、DELIVERY、DESIGN、i18n、PERFORMANCE，以及 SDK README、教程、协议、加载、Invocation、存储、目录、UI 生命周期、客户端、类型、示例、版本与发布清单。文档准确描述最终安装结构；历史设计保留状态说明，不冒充当前实现。

第三方教程分三条：最简单的普通 Provider；独立按需加载插件；可选参数动作／大目录。每条都有独立可运行示例、必选与可选项、错误和取消示例，不要求开发者先理解 Host 内部架构。

只删除已证明失去入口、被替代且回归覆盖的旧代码；动态注册、TOC 加载和第三方公开 API 不能仅凭文本零引用判死。最终交付分别列出功能、SDK、性能、UI、存档和客户端验收状态，不再用“代码已提交”替代“整个计划完成”。
