# 整窗开关动画与黑框回归

基线5c99a17。用户要求重构主面板打开/关闭，其他控件动效和业务保持不变。PERFORMANCE.md的经验总结按用户要求暂缓，本记录仅记此次修复证据。

## 实机反馈

黑色圆角背景存在，所有内容不显示。最初聊天诊断经粘贴转换，`f:IsShown()`等变成`f()`；09:40:20落盘的BugGrabber记录明确包含该命令错误，它不是面板运行错误。后续改用点调用。

手动关闭后采样的alpha=0、动画任务结束是正常关闭终点，不能据此判定动画异常取消。固定流程Show→1秒后读取，得到`OPEN true true 1 1 nil`：根及标题alpha=1、动画正常结束。仅把外层presenceViewport的SetClipsChildren改为false后，用户确认“出来了”。证明外层原生裁剪参与了整树不可见；没有证据断言引擎内部失效机制。

用户随后观察到关闭时输入框超出背景，要求重构整窗动画。此次移除整个分层收缩结构，不做每次打开关闭裁剪的补救。

## 实现与预算

背景七个纹理区域和顶栏/正文/底栏共用根节点，移除三个额外Frame；正文原有列表裁剪保留。开关固定宽高和缩放，仅根节点平移及整体淡入淡出。距离44界面单位、440/320ms、Hermite保留反向速度；位移按有效缩放舍入为整屏幕像素。

一个懒创建驱动、一个复用任务表、最多一个活动任务；每帧最多根节点SetPoint/SetAlpha两次调用，同值跳过。无新增媒体、常驻事件或空闲回调，不运行强制GC。1000轮重复开关累计分配预算保持<512KiB，不新增Frame/动画组。布局只在非战斗修改，进入战斗由既有安全隐藏路径收尾。

## 验证与限制

旧代码在新增共同根节点断言上失败（interaction_smoke.lua原1176行），移除分离层级后通过。该断言锁定布局契约，不声称替身能模拟原生裁剪器。

专项测试覆盖固定宽高/缩放、整屏幕像素位移、起止状态、反向位置/速度、重复关闭、30/120Hz、冷/热12轮×6采样、减少动态效果、原生Esc、战斗、重入和结束清理。1000轮分配179.69KiB、新增Frame/动画组0、结束后OnUpdate=nil。离线耗时约78–90ms/1000轮，不等同于游戏帧时间。

`powershell -NoProfile -File tests/check_contract.ps1`完整通过，输出保存在本机临时目录`lychee-presence-rebuild-check.log`。Lua/XML/TOC契约、生产UI集成、内存预算及git diff --check通过；wowdoc validate检查79个Lua文件，valid=true，无诊断。首次面板创建从62减少为59个Frame。
