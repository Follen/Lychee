# 成就持久目录与增量更新

实现前约束：缓存只保留最近使用角色的一份 ID/标准化名称目录，按 schema/build/product/locale/角色 GUID 区分，不共享其他角色的光辉事迹可见性。最多 32,768 条、名称单条 512 字节、名称累计 4 MiB、分类 512 个；必须验证历史数据，不信任 SavedVariables。

正常启用：分批验证并复用缓存数组，创建运行时 ID→位置索引，再只比较分类数量。分类不一致、缓存无效、版本/语言/角色变化或距上次完整扫描超过 7 天时分批重建。分类数量无法发现同数量替换，因此保留 7 天完整校验，且只在启用时检查时间，不新增常驻 timer。此次优先落地事件按 ID 增量；离线漏事件后分类不一致先采用完整重建兜底，不宣称已经实现按分类重建。

ACHIEVEMENT_EARNED 仅记录 ID，最多 256 个去重待更新 ID，超限改为一次完整重建；更新对应条目及前后系列、相关分类计数。事件风暴仅一个任务；战斗只记录任务并暂停，脱战恢复，空闲进入/离开战斗不扫描。CRITERIA_UPDATE 不注册，状态、点数、图标、描述及条件仍按搜索结果实时读取。

预算：不新增 Frame、常驻轮询或高频事件；原有 128 条/约 1 ms 批次门槛不变。6002 条缓存+运行索引保留 <4 MiB；热启用全量 GetAchievementInfo 目录读取应为 0；单个无系列获得事件只读取目标成就，不扫描分类目录；队列最多 256 个，停用后无 timer/job/事件/运行索引，SavedVariables 目录明确保留。新增索引成本与冷热 API 次数单独记录；游戏内持久化加载时间和原生 API 延迟待实测。

## 实际验证

版本前基线 69981dd：每次启用扫描全部成就、每次获得和脱战重新扫描。现在 6002 条目录+索引保留约 693.5 KiB（前一版同测试目录约 563.4 KiB，新增主要为 ID 位置索引）。10 次热启停总 CPU 27 ms、累计分配 1356.4 KiB、回收后增长 0.0 KiB、GetAchievementInfo 目录读取 0 次；普通获得事件读取目标 1 次，空闲进出战斗工作 0。数字为 Lua 5.1 模拟，不代表游戏加载时间；热启用仍需 O(N) 校验和构造索引，但没有 N 次原生目录读取。

历史缓存验证每 16 个便宜元数据检查调用一次 checkpoint，所以元数据批次最多约 2048 次检查并按约 1 ms 让出；原生分类计数/成就读取仍逐次 checkpoint。SavedVariables 的 Lua 加载成本无法被此分批抢占，必须作为实机待测项。未知缓存顶层字段在验证后丢弃，条目数组的稀疏/额外 key、重复 ID、类型、长度、总字节和分类数量受检查；无效缓存撤销后重建。增量以单条 ID/文本成对提交，取消时已完成条目保持一致，待完成 ID 保留并可重试；新事件使旧协程失效，不能覆盖新任务。

回归覆盖首次搜索、持久缓存复用、获得 ID 更新、战斗排队恢复、停用注销、重复启停、重复 ID 缓存损坏、7 天过期、角色/build 切换、离线分类计数漂移、257 个事件过载及原有搜索/分享行为。没有注册 CRITERIA_UPDATE。共享 CatalogProvider 不修改，仅成就覆写 MarkDirty 与 onEvent，以避免影响其他 Provider。

API 证据：wow-ui-source / retail / latest / 8ea15b61e45c0ed4eba01439c90757f86eb78d34，GetServerTime、UnitGUID、GetAchievementCategory 与 ACHIEVEMENT_EARNED 的 path/line/excerpt 见 achievement-cache-api.json。原生界面及 SavedVariables 沿用已有声明，不增加 TOC 模块。游戏内首启/热重载耗时、战斗/团本帧时间、SavedVariables 文件体积与真实账号数据仍待验证。来源关闭会保留这份缓存，所以不宣称零常驻内存；它只保证零活动工作。更新后第一次建立缓存，后续 /reload 复用。回滚用新的 revert 并同步。
