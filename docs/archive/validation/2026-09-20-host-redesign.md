同一离线 zhCN Mainline 全运行文件加载：基线 127 文件，2278.6 KiB 保留、5328.2 KiB 累计分配、33 ms；本轮 131 文件，2309.5 KiB 保留、5401.8 KiB 分配、38 ms。两者均 2 Frame / 4 Host 事件，没有新增加载期 UI 或空闲工作。单次 CPU 仅为样本，均在 61 ms 门槛内，不宣称尾延迟改善。约 30.9 KiB 增量来自共享冷却、动作结果及定义接口的代码/常量；没有增加全量业务目录。新增功能的离线成本接受，完整游戏场景仍不能由离线数据代替；本次有界实测见下节。

冷却固定一行 1000 次绑定/刷新/释放：4 ms、781.3 KiB 累计分配、0.0 KiB 回收后增长、0 新 Frame。复用原生框体，最后观察者离开后组表/事件/任务清零；原生纹理和引擎对象另待实机测量。1000 来源设置页仍 8 行控件、359 个替身对象，20 次刷新约 44 ms / 0.4 KiB，池不增长。以上不代表游戏 CPU 或整体内存下降。

候选实验 `tests/performance/candidate_materialization.lua`：100 次文档结果物化 20 候选，36 ms / 5996.3 KiB / 2000 reader；预知最终只需 10 候选的对照，18 ms / 2872.9 KiB / 1000 reader。该对照预知赢家，未证明个性化/别名完整排序等价；如果等待动态来源得出赢家，会损失首批静态可点击结果，最坏等待查询 5 秒截止。因此不接入该执行链，保留渐进发布；新增诊断只记录有界标量且默认关闭。
