# 成就共享目录与角色差异：实施前约束

基线 27eb58c。用户要求共享公共目录、角色差异独立保存，并保留最多十个角色。采用同 build/product/locale 内不可变参照目录，角色仅存连续引用区间、无法共享的条目和后续按 ID 更新。以各角色实际枚举结果编码，不假设跨角色可见性或同 ID 名称一定相同；保持条目集合、顺序、文字和动作一致。新角色首次仍枚举验证，缓存命中不调用全量成就目录 API。

所有者为成就 Provider；SavedVariables schema 3。公共条目最多 32768 个；所有存储条目（公共、差异、更新）合计最多 65536 个、名称合计 4 MiB，区间编码最多 65536 个整数，最多十个角色，LRU 淘汰。公共目录以外的缓存都可淘汰；极端差异超过预算时当前角色也可不持久化，但运行时结果完整，不截断搜索数据。单份目录依旧最多 32768 条、名称单条 512 字节。禁用释放活动目录和位置索引，保留公共目录与角色差异；无新增 Frame、事件、轮询。战斗暂停，单事件只更新目标与系列，现有 128 次 checkpoint/约 1 ms 门槛不变。

预算在实现前调整：固定 6002 条单角色保留仍 <4 MiB；10 次热启停临时分配预算由 4 MiB 改为 8 MiB，原因是恢复时为当前角色物化独立可变数组，避免事件更新污染共享目录。要求十个相同角色持久化无十份条目数组，序列化大小相对同格式独立完整目录十份降低至少 70%；10 次热启停 GC 后增长 <64 KiB，原生成就目录读取为零。报告前后实际分配和 CPU，不用存储收益代替热恢复成本。角色差异、移除/新增、同 ID 不同名称、11→10 淘汰、重载序列化往返及按 ID 更新不污染另一角色需要独立回归。

共享是按内容相等证明的存储去重，不是假定公共可见集合；完成状态、进度、图标与分享链接仍即时读取。七天完整审核及分类变化局部枚举保留。旧格式首次重建一次；真实客户端 SavedVariables 载入、首次结果、战斗/团本帧时间待实测。


## 初步结果与限制

固定 Lua 5.1 测试，6002 条单角色保留约 1336.4 KiB（前版 822.9 KiB）；10 次热启停累计分配约 6524.4 KiB（前版约 1382 KiB），GC 后增长 0.0 KiB。新增活动数组与共享目录位置索引是明确代价，满足实施前调整的 8 MiB 预算。参考 CPU 10 次共 48–52 ms，接近前版约 47 ms；采样数量不足以声称耗时改善。批次模拟峰值约 2 ms 受时钟粒度影响，不代表客户端峰值达标。

十角色序列化共 320575 字节，对照相同目录各自完整存储 2767501 字节，减少 88.4%。输入含两个分类、6002 条及少量分类差异，非真实账号存档。公共+差异实际存储 7002 条、111046 字节名称；引用区间保留精确目录顺序，SavedVariables 序列化/反序列化后仍复用，不依赖 Lua 内存对象别名。新角色首次仍读取当前角色的真实目录，不能将去重存储宣传为新角色零初始化。

新增回归：十角色保留与第十一角色 LRU 淘汰；两个角色可见范围不同；同 ID 名称不同；共享目录不可被角色事件修改；稀疏新增/覆盖经过序列化重载后恢复；损坏角色引用不损坏公共目录与其他角色；历史输入总字节超限时淘汰而不改变当前结果。无目录元数据变化的获得事件不追加重复差异记录。角色完整/分类重建时会重新压缩差异；公共参照在同域内保持不变，版本/语言变化后替换。

API 来源：wow-ui-source / retail / latest / 8ea15b61e45c0ed4eba01439c90757f86eb78d34，source check 无更新。精确 path/line/excerpt 见 achievement-shared-api.json；分类总量由 AchievementFrame_GetCategoryNumAchievements_All 使用 GetCategoryNumAchievements(categoryID)；其余既有 API 证据沿用 achievement-cache-api.json。本次共享仅根据实际内容相等编码，不从 API 推断跨角色身份或可见性。未新增 API/事件/Frame，未改动分享动作与实时结果物化。游戏内首次/热重载、持久化体积、战斗/团本帧时间继续待验证。


## 最终验证

三轮前后交替测试（同 6002 条、相同热启停 10 次）：前版 CPU 47/51/50 ms，中位数 50、最大 51；新版 48/49/52 ms，中位数 49、最大 52，不声称尾延迟改善。前版累计分配 1381.8–1382.8 KiB，新版 6524.7–6525.4 KiB；GC 后保留增长均 0.0 KiB，目录 API 热读取均 0。旧版本代码及测试从 27eb58c 读取到临时目录，仅替换测试加载路径，未改测量输入；新测试仅相同阶段做格式适配，后续新增十角色与差异回归。原始输出见 achievement-shared-benchmark.txt，初始基线见 achievement-shared-before.txt。

极端容量测试也已通过：共享参照与当前目录的差异合计超过 4 MiB 时，不保存当前角色缓存，但当前 6002 条仍完整、查询返回正常；无静默截断。测试模拟的是分配与行为，实际历史 SavedVariables 的解析发生在插件代码之前，无法由分批校验控制；输入验证每块最多 32768 条、十个角色、单名称 512 字节，完成后严格应用全局预算，不保留未经验证的未知字段。

完整 tests/check_contract.ps1 通过（含原有搜索、分享、安全动作、UI、各 Provider 回归）；所有运行时 Lua 经 luac -p 通过，XML 解析通过、TOC 契约通过，wowdoc validate valid=true（46 个 Lua），git diff --check 通过。原始输出见 achievement-shared-checks.txt 和 achievement-shared-wowdoc.json。未更改 TOC/加载模块；交付后 /reload 即可，新 schema 首次重建一次。游戏内实测未执行，保留为待验证项；回滚使用新 git revert 并按相同流程同步。
