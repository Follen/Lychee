# Mount click dispatch

User report: clicking 鎏金雷龙 has no effect. Existing tests verified secure attributes and simulated cast completion, but never verified a call to the mount collection summon API. The old path configured type=spell, which current SecureTemplates.lua routes through CastSpellByID. Blizzard's MountJournalMountButton_UseMount instead uses C_MountJournal.SummonByID(mountID).

Policy.Check now resolves a collected, character-visible mount from the spell ID before treating it as a spellbook action. The pooled button retains that mount ID and has no secure spell action type. Its hardware PostClick requests SummonByID only after PreClick validates the current result and marks the cast pending; it rejects combat and catches API failure. Normal spell buttons keep their existing secure type. Real spellcast events still determine success, closure and recency; failed API calls clear pending state and keep the palette open. Release clears the mount ID for safe pool reuse.
