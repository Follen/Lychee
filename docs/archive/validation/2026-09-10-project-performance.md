# 全项目性能审查与优化

基线提交 `4e12531`。按根目录 PERFORMANCE.md 完整审查运行时 39 个 Lua 文件、Bindings.xml、Lychee.toc、40 个媒体/许可文件及开发包加载边界。三条并行工作线使用同一工作区，主 Agent 负责搜索、集成、交叉审查与统一交付；没有改变保存数据 schema、视觉布局或游戏动作定义。

本文所有数字均为 Windows Lua 5.1 离线测试，不能替代 WoW 插件内存、引擎对象、战斗 CPU、帧时间或 taint 实测。基线由 `git archive 4e12531 package/Lychee` 提取；完整原始数据保存于本节引用的 JSON。运行时不增加 profiling、强制 GC 或后台轮询。

未把所有结果包装成 CPU 提升：Core 隔离的单条更新耗时中位数仍为 4 ms，Boundary 最大样本未下降。Scheduler 为确保轮次、重入和错误恢复，256 个空回调增加一次复用快照和保护调用，总平均成本约 0.017 → 0.034 ms/tick；当前没有生产订阅，不能列为游戏帧率收益。它保留零临时分配，并以 256 为内部防御容量，满额显式拒绝，不丢弃已有玩家动作。

**常规查询没有显著总量下降。** 2,689 条相同数据、48 次相同查询，三轮交替对照的回收后常驻 7,828.1 → 7,832.1 KiB，累计分配 2,315.5 → 2,317.0 KiB，中位单次查询约 0.354 ms 持平；新增固定规则和生命周期保护带来约 4 KiB 常驻与 1.5 KiB/48 次分配，仍通过原有 9 MiB / 4 MiB 预算。本轮收益主要出现在设置规模、事件刷新、边界验证和长会话保留，而不是此前已经优化过的常规查询。[整体原始输出](../design/2026-09-10-project-perf-combined-results.json)

## 交叉审查发现与修复

虚拟化第一版暴露了原来固定行位置下不明显的身份问题：按住排序/删除/开关按钮后滚动，再松开会对新绑定记录操作。测试先复现失败，再加入绑定代次与 pin/provider 对象身份校验；重绑、同索引替换、隐藏重开和禁用恢复后的旧点击被拒绝。保留正常硬件点击及现有直接调用测试语义。另一 Agent 复核确认原复现通过；不能把仅清 hover 当作取消旧动作。

非 UI 改动由另一工作线交叉审查，重点检查 Provider 取消重入、晚到回复版本、Scheduler 替换完成、技能提交失败恢复和安全事件启停，未发现其他阻塞问题。交叉审查和离线替身均不证明真实 WoW 事件时序。

## 验收入口

`powershell -NoProfile -File tests/check_contract.ps1` 统一执行 20 组测试：原有 14 组完整保留，增加以下 6 组，不放宽既有预算。

- `performance_search.lua`：全部 256 字节及混合中文规范化参照、固定分配预算、长文本缓存、源失效键、关闭释放。
- `performance_ui.lua --check`：视口池与分配预算、滚动末项、拖动、按下后重绑身份、关闭重开、战斗短路。
- `performance_core.lua`：Boundary 分配预算、Scheduler 有界轮次/重入/错误恢复、Ready 取消清理。
- `perf_core_provider.lua`：增量更新分配预算、任务积压、晚到 reply、取消回调重入及注销。
- `performance_builtin_secure.lua`：禁用、启停、加载事件、无变化提交、增量修改、提交失败回滚、战斗恢复。
- `perf_builtin_secure_events.lua`：零空闲订阅、PreClick 订阅、成功/失败/释放撤销、战斗 dirty 恢复。

最终还需运行全部 39 个运行时 Lua 的解析、XML/TOC 引用检查、wowdoc validate、git diff --check，并在提交成功后同步和校验文件。实际执行输出另存 [统一验证记录](../design/2026-09-10-project-perf-verification.json)。游戏场景未完成不写为通过。

## 保留的边界与游戏验证

- 全量技能书变化和不带 ID 的坐骑收藏事件仍需同步读取目录；本轮减少无变化提交和无关触发，没有声称消除全部扫描。使用实际客户端数据进一步评估单批最坏耗时。
- Settings 元数据刷新仍按 N 整理/排序；滚动只处理可见 K。正常 Pin API 上限 64；手工超量 SavedVariables 不截断、不删除、不静默丢失，迁移/首页数据处理仍随原始输入增长。
- 第三方同步回调不能被抢占，其自行创建资源或长期保存 reply 的行为超出宿主释放保证。宿主限制每轮工作和结果量，不能保证任意外部代码符合预算。
- 必需的 Bootstrap 事件入口、延迟复用的 Frame/纹理和静态目录记录仍可常驻；“零空闲回调”不等于插件占用零内存。
- 游戏未实测：登录/首次打开、空闲、单目标战斗、团本/姓名板峰值 CPU 与帧时间，技能点击结果/失败、战斗中关闭及脱战恢复、真实滚轮/拖动/缩放/裁剪。同步后使用 `/reload`，按相同数据和步骤记录这些场景。
- 任何不符合预期的行为应以本次统一提交做新的 `git revert`，检查通过后按相同流程同步；不改写已交付历史。
